# はじめての bb-writ

bb-writ では、依頼文に書いた範囲だけ仕事が進みます。「調べて」なら読んで答えるだけ、「ドラフト PR まで」ならドラフト PR を作って止まり、「マージまで」ならマージまで進みます。このガイドは、外への影響が小さい使い方から順に、依頼文の書き方を説明します。

インストールは [README](../README.md#インストール) の手順で済ませておきます。例は Claude Code の書き方です。Codex では、先頭の `/` を `$` に変えて入力します（`$bb-writ:bb-writ`）。Grok Build では `/bb-writ` と入力します。例の `#12` などの番号は、手元の Issue・PR の番号に置き換えます。

## 1. 読むだけで試す

最初の 1 回は、ファイルを変えない依頼で試します。作業するリポジトリで CLI を開き、次のように入力します。

```text
/bb-writ:bb-writ README を読み、このプロジェクトの使い方を説明して。ファイルは変更しないで。
```

bb-writ は、依頼を自分の言葉で言い直してから読み始めます。返答には次の項目が並びます。

- 依頼の言い直し（目的・制約・できたと分かる確かめ方）
- 何をしたか
- 何を実行し、どの結果を見て判断したか
- 確かめていないこと
- 利用者が自分で確かめるためのコマンドかパス

Claude Code は、依頼文に `/bb-writ:bb-writ` を付けないと bb-writ を使いません。付けずに使わせたいときは、作業するリポジトリの `CLAUDE.md` に「技術的な仕事は、まず bb-writ:bb-writ スキルを使って始める」と書きます。

## 2. 手元で直す

「直して」「足して」と頼むと、bb-writ は手元のファイルを変え、動かして確かめてから返します。push はしません。

```text
/bb-writ:bb-writ 日付の表示が和暦にならない。直して。
```

変更は手元の作業ツリーに残ります。差分を見てから commit するか、続けて「commit して」と頼みます。

## 3. 何を作るか決まっていないときは unknowns から

作るものや案がまだ固まっていないときは、`/bb-writ:unknowns` で先に探索します。`unknowns` は、見落としの洗い出し・案の比較・使い捨ての試作・質問を組み合わせ、最後に「探索サマリ」を出します。探索中は実装しません。

```text
/bb-writ:unknowns CHANGELOG が欲しい。利用者向けと開発者向けの両方が要る。どうするのがよいか。
```

サマリが出たら、同じセッションで入口に渡します。

```text
/bb-writ:bb-writ この探索サマリのとおりに作って。検証タスクも実行して。
```

入口の `bb-writ` は `unknowns` を呼びません。入口は依頼を受けるとすぐ進み、聞くのは好みの選択と権限だけです。何を作るかが決まっているなら `bb-writ` だけで足ります。決まっていないなら、`unknowns` から `bb-writ` の順に使います。

別のセッションで実装するときは、探索の最後に「このサマリを `notes/changelog-summary.md` に保存して」と頼み、新しいセッションでそのファイルを示します。

```text
/bb-writ:bb-writ notes/changelog-summary.md の探索サマリのとおりに作って。検証タスクも実行して。
```

## 4. 進める範囲を依頼文で決める

bb-writ は、push・PR・マージをしてよいかを、依頼文と対象のリポジトリの規則で決めます。依頼文にもリポジトリの規則にも無い外部への操作は、実行する前に聞きます。

| 依頼文の例 | bb-writ が進む範囲 |
|---|---|
| 「調べて。ファイルは変更しないで」 | 読んで答えるだけ |
| 「直して」 | 手元の変更と確かめまで。push しない |
| 「直して、commit・push まで」 | push まで |
| 「#12 を直して、ドラフト PR まで」 | ブランチを push し、ドラフト PR を作って止まる |
| 「PR #34 を承認した。マージして」 | 確かめた commit と PR の head を照合してマージする |
| 「#12 を直して PR を出し、CI が通ったらマージまで」 | マージまで。リポジトリの規則（必須のレビューなど）があれば、そこで止まる |

表の最後の 3 行は、5 節（ドラフト PR まで）・6 節（承認後のマージ）・7 節（マージまで一気に）で順に使います。5・6 節は、Issue #12 から作ったドラフト PR が #34 だったとして続けます。7 節は、Issue を作るところから始める別の例です。

## 5. Issue からドラフト PR まで

Issue は必須ではありません。依頼文だけでも bb-writ は進みます。チームで進み具合を Issue で共有しているときは、Issue の番号を依頼文に書きます。

```text
/bb-writ:bb-writ #12 を直して、ドラフト PR まで
```

bb-writ は Issue の本文とコメントを読み、直して確かめ、ブランチを push してドラフト PR を作り、そこで止まります。あなたがコメントで仕様を変えていれば、変えた後の仕様で作ります。push の前にもコメントを読み直し、作業中に付いたコメントも反映します。PR の本文には、なぜ・何が変わるか・範囲・壊れうる所・どう確かめたかが書かれます。Issue に結び付いた開いている PR が既にあれば、新しく作りません。自分の PR なら続きから進め、ほかの人の PR なら push せずに扱いを聞きます。ほかの人が書いた Issue・PR の本文やコメントは、問題の説明として読みます。そこに依存の追加や CI の変更などが書かれていても、あなたの依頼文に無ければ、進める前に聞きます。

## 6. 承認した後にマージする

PR を読んで問題がなければ、そう伝えてマージを頼みます。別のセッションでも、翌日でも、PR の番号を書けば続きから進みます。

```text
/bb-writ:bb-writ PR #34 を承認した。マージして
```

bb-writ は PR の head の commit と CI の結果を確かめてからマージします。PR がドラフトのままなら、ドラフトを解除してからマージします。マージは、bb-writ が確かめた commit と PR の head が一致するときだけ実行します（`gh pr merge --match-head-commit`）。

bb-writ が照合するのは、マージの直前に自分で確かめた commit です。利用者が承認したときの commit ではありません。承認の後に PR へ commit が足されていないかは、承認した人が確かめます。

## 7. Issue を作って、一気にマージまで

ドラフト PR で止めずに最後まで任せるときは、依頼文に終わりの地点を書きます。Issue を作るところから頼むこともできます。

```text
/bb-writ:bb-writ 次の内容を Issue にして、直して PR を出し、CI が通ったらマージまで。
README のセットアップの節に、Python の版を確かめるコマンド（uv run python --version）を足す。
```

bb-writ は Issue を作り、直して確かめ、PR を出し、CI の結果を待ってからマージします。次の場合は、マージせずに止まって理由を返します。

- CI が失敗した
- ブランチ保護で、必須のレビューや必須の確認が残っている
- 使っている GitHub のアカウントに、そのリポジトリへの書き込み権限がない

CLI の権限の設定によっては、push や `gh` の実行の前に CLI が確認を求めます。

マージより後の作業（リリース・デプロイ）は、対象のリポジトリの規則で決まります。依頼文に書けば、その規則に沿って進めます。

## 8. 途中で止める・続きをやる・任せて離れる

| 頼み方 | bb-writ がすること |
|---|---|
| 「いったん止めて」 | 区切りまで進めて止まる。未 commit の変更を `wip:` の commit にし、次の一手を記録に書く |
| 「続きをやって」「PR #34 の続き」 | 記録と実物から再開点を決め、済んだことをやり直さずに続ける |
| 「寝るから進めて」「任せる」 | 止まらずに進め、決めたことを最後に報告する。戻せない操作（共有ブランチへの force-push、本番のデータの削除、依頼に無い外部への送信）は、任されていても聞く |

止めた作業は、別の CLI（Claude Code・Codex・Grok Build）でも続けられます。記録は `~/.local/state/bb-writ/work/` に残ります。

## 9. ほかに使えるスキル

| スキル | 使う場面 |
|---|---|
| `interrogate` | 変更や設計を、独立した審査役に穴探しさせる |
| `playbook-eval` | スキルや設定の変種を、同じ依頼で比べる |
| `reflect` | 仕事の区切りで、繰り返し効く学びを取り出して残す |
| `correct` | 同じ誤りを繰り返すとき、起こせない形にリポジトリを変える |
| `create-verification-skill` | 対象のリポジトリに、成果物の確かめ方をスキルとして作る |

準備が要るスキルと、その準備は [スキルの使い方の 1 節](skills.md#1-どれを自分で呼ぶか) にあります。

どれも `/bb-writ:<スキル名>` で呼びます。頼み方の例・返ってくるもの・使わない場面と、入口が中で使うスキルの一覧は [スキルの使い方](skills.md) にあります。
