# フォールバックよりエラー出力

想定外の状態は、捕まえて、原因が分かる形で出して、止める。黙って既定値を入れたり、別の経路に逃げたりしない。guard・fallback・既定値の代入が正当なのは、止めることができない場合だけ。

**なぜ:** 黙って続けた処理は、後で見つけにくい誤りになる。止まった処理は、その場で直せる。「動いているように見える」が最も高い。

**適用する場面:**
- 例外を捕まえて続けようとしたとき。
- 無いファイル・無い鍵・空の値に既定値を入れようとしたとき。
- 検査が落ちたのに「環境のせい」と判断して先へ進もうとしたとき。

**やること:**
- 止まる理由を、落ちたコマンド自身の文脈（何を・どこで・なぜ）で出す。直し方が分かる文にする。
- 環境の失敗（権限・網・道具の不在）と、成果物の欠陥を分けて報告する。どちらも合格にはしない。
- 既定値を入れるなら、それが正しい値である根拠を同じ場所に書く。

**使わないとき:** 停止そのものが害になる場所（配送の途中で止めると外部が不整合になる操作）では、実際の状態を照合してから続ける。それは fallback ではなく照合。

**確かめる例:** 失敗の出力から、読み手が原因と直し方に到達できる。`except: pass` や無言の既定値が差分に無い。
