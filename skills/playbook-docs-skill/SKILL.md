# 手引き: docs-skill（文書・スキル・知識の変更）

README・手引き・SKILL.md・知識ベースを、読者が目的を達成できる形に直す。文章が整っていることは完成ではない。

1. **読者と目的を決める。** 誰が、何をしたくて読むか。「読者がその手順で目的を達成できる」を確かめ方にする。スキルなら「意図した依頼で使われ、意図しない依頼で暴発せず、必要な行動に至る」。知識なら「出典をたどれ、必要な情報を見つけ、矛盾を区別できる」。
2. **事実を実物で確かめる。** 文書が指すコマンド・パス・名前・数値を、リポジトリと実行で照合する。CI の定義・スクリプト・ディレクトリの実体が正本で、文書は従。英日の対（README.md と README.ja.md）は両方を同じ変更で直す。
3. **既存の規則に従う。** そのリポジトリの文体・用語・節の形・機械の検査（lint・スキャン・リンク検査・公開前の検査）を読み、同じ形で書く。新しい規則を持ち込まない。
4. **書く。** 1 文 1 事。読者が次に取る行動が分かる文。推測の語（「はず」「たぶん」）を事実の文に混ぜない。
5. **確かめる。** そのリポジトリの文書の検査をすべて実行する。手順の文書は、書いたとおりに実行して通ることを確かめる。スキルや手引きの変更は、文書だけを渡した新しいセッション（別の子）に代表的な依頼を遂行させ、成果物を見る（読者役）。読者役の成功報告でなく、成果物で判断する。キーワードが含まれているかの検査を完成にしない。
6. **仕上げ。** 変更の理由と、確かめたこと・確かめられなかったことを本文に書く。

返答: 読者と目的、何を直したか、実物との照合で分かったこと、実行した検査と読者役の結果、確かめていない範囲。
