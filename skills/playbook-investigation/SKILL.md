# 手引き: investigation（読んで答える）

何も変えずに、根拠付きの答えを返す。「どうなっている」「なぜこうなっている」「どちらがよいか」「変えないで調べて」。

1. **問いを言い直す。** 何が分かれば利用者は次に進めるか。答えの形（説明・比較表・推奨・再現手順）を決める。
2. **根拠を集める。** コードと設定（いまどう動くか）、履歴（`git log -S`・`git blame`・PR・Issue。なぜこうなったか）、実行（確かめられるなら動かして観測する）。読んだ場所と実行したコマンドを控える。大きな対象は、範囲を分けて読み取り専用の子に出し、要約でなく事実（パス・行・値）を受け取る。
3. **事実と推測を分ける。** 直接の根拠がある文と、「〜と見える」の文を書き分ける。記録が無いことも答え（「誰も理由を書いていない」）。
4. **答える。** 結論を先に、根拠を次に。比較なら、観点ごとの表と推奨と、推奨が変わる条件。再現手順を頼まれたら、そのまま実行できるコマンドで。
5. **変更が要ると分かったら、ここでは変えない。** 「次に何をすればよいか」と「その確かめ方」を書いて返す。利用者が頼めば、別の手引きで始める。

返答: 結論、根拠（読んだ場所・実行したこと）、推測と断った箇所、次にできること。

入口 `bb-writ` から始めた仕事で会話が要約された後は、入口を呼び直して全文を読み直す（要約の後は、先に呼んだ入口が落ちていることがある）。
