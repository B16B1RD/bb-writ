# 実装でなく振る舞いを試験する

試験は、コードがその利用者（呼び出し元・使う人・別のサービス）に何をするかの主張にする。振る舞いは、利用者が使う接点から観察できること（返り値・エラー・読み戻せる状態・外への作用）。実装は、観察できないこと（内部の補助関数・呼び出しの順番・途中のデータ）。

**なぜ:** 内部に結び付いた試験は、リファクタのたびに書き直しになり、それでも不具合を捕まえない。振る舞いを見ない試験は、通っても何も証明しない。

**適用する場面:**
- 新しい試験を書くとき。
- リファクタで既存の試験が落ち、試験の方を直そうとしたとき。
- 解析の出力を、コードを 1 回走らせた結果の写しで固定しようとしたとき。

**やること:**
- 2 つの仮の変更で試験を判定する。振る舞いを壊す（誤った値を返す、作用を飛ばす、作用を 2 回する）と落ちるか。観察できる結果を保ったまま内部を組み替えると通るか。両方を満たす試験を残し、残りは書き直すか消す。
- 利用者の接点から具体的な入力で動かす。期待値は試験対象のコードの実行からでなく、要件から導く。
- 決めるのは約束で、確かめ方の形ではない。外部のサービスが受け取る内容は振る舞い、内部の補助関数の呼び出しは実装。呼び出し側が分岐に使うエラーの型は約束で、誰も読まないエラーの文言は固定しない。「呼ばれない」を確かめるなら、呼ばれる場合の試験と組にする。

**使わないとき:** 約束が呼び出しでなく不変条件（2 つの表に同じ鍵がある、型の検査が通る）のときは、観察の接点を探さず、不変条件を直接固定する。それがその場合の振る舞い。

**確かめる例:** 試験の期待値が要件の文から読み取れ、試験対象のコードで計算されていない。内部の関数名を変えるだけで落ちる試験が無い。
