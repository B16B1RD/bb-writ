# 最小の変更で解く

問題を解く最小の変更をする。同じ判断を何か所でも繰り返さず、1 か所で決めて、結果を単純な値（フラグ）で渡す。少ない行は、整って見える定型より価値がある。

**なぜ:** 差分が小さいほど、読み手が確かめる範囲が狭く、誤りの入る余地も小さい。同じ判断が散らばると、1 か所だけ直して食い違う。判断を層ごとに引き回すと、どこで決まったかを追えなくなる。

**適用する場面:**
- 依頼に対して差分が広がり、関係の無いファイルまで変わったとき。
- 同じ条件（対象の種類、環境の有無）を複数の関数で判定しようとしたとき。
- 値を 1 つ通すために、間の関数すべてに引数を足そうとしたとき。

**やること:**
- 繰り返す判断は 1 か所（設定を読む関数、対象の表）で決め、呼び出し側には結果だけを渡す。
- 差分を出す前に、依頼を満たさない行（ついでの整形・名前の変更・使わない補助関数）を外す。
- 消して同じ結果になるなら消す。足す前に、削る案を先に試す。

**使わないとき:** 最小の差分では誤りが残る場合（同じ欠陥がほかの場所にもある、原因が別の層にある）。そのときは必要な範囲まで広げ、広げた理由を書く。

**確かめる例:** 差分の各行が、依頼のどれかに対応している。同じ条件式が複数のファイルに現れない。
