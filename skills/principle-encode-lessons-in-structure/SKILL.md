# 教訓は構造に組み込む

繰り返す教訓は、文でなく構造（lint・メタデータの印・実行時の検査・スクリプト）にする。構造で直せるなら、構造だけで直す。指示の文は症状。

**なぜ:** 文は読まれたときにしか効かず、効くかは読み手の判断に任される。構造は毎回、誰に対しても効く。同じ指示を 2 回書くのは、1 回目の文が効いていない証拠。

**適用する場面:**
- 手引きやスキルに、前と同じ注意書きを足そうとしたとき。
- レビューや訂正で、同じ指摘を 2 回受けたとき。
- 「次は気を付ける」と報告に書こうとしたとき。

**やること:**
- 強い形から選ぶ。作り（誤りようの無い設計）→ 型 → lint・CI → 試験 → 手引きの文、の順に見て、効く最初の形にする。メタデータの印は、frontmatter の項目のように機械が読める場所に置く。
- 構造で塞いだら、同じ内容の文は足さない。既にある文は消すか、構造への参照にする。
- 判断が要って構造にできない教訓は、指示を目立つ場所に移し、失敗の実例を 1 つ添える。

**使わないとき:** 1 回だけの出来事。どこに置くか（製品か、対象のリポジトリか）は `principle-route-lessons` で決める。

**確かめる例:** 訂正の後の差分に、検査・型・スクリプトのどれかがあり、同じ内容の注意書きが増えていない。
