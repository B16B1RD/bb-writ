# 実物で確かめる

作業の成果は、実物を直接見て確かめる。代わりの指標・自己申告・「ビルドが通った」から推し量らない。

**なぜ:** 確かめていない成果は、正しさが分からない。間接の確かめ（ファイルの更新時刻、出力の新しさ、子のエージェントの報告、前に撮った画面）は安く見えるが、誤った推測で動く費用は、元を見る費用よりずっと大きい。

**適用する場面:**
- 「完了しました」と報告を書く直前。
- 子のエージェントや別の工程が「できた」と返してきたとき。
- 解析の結果・生成した文書・常駐の処理の様子を、ログや状態ファイルから判断しようとしたとき。

**やること:**
- 動く物は動かす。解析なら実際の出力の値を読み、文書なら描画した結果を見て、常駐の処理ならプロセスの生存を直接確かめる。
- 確かめが落ちたら、系を疑う前に観察の方法（見ている場所・版・キャッシュ）を疑う。
- 確かめはできるだけスクリプトにし、同じ比較を再実行できる形にする。その出力を証拠として残し、読み手が言葉を信じる代わりに再実行できるようにする。

**使わないとき:** 無い。確かめのスクリプトと出力を対象のリポジトリに commit するかは別の判断で、後から追える記録が要る大きな作業（移植・移行）だけにする。小さな変更では、報告に添えて人間に見せる。

**確かめる例:** 完了の報告に、実行したコマンドと実際の出力（値・画面・差分）が添えてある。「〜のはず」「報告によれば」で終わる文が無い。
