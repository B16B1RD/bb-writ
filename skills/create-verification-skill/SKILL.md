# 検証スキルを作る

対象のリポジトリに、利用者が成功を観測する場所で成果物を確かめる手順を、スキルとして残す。読むのは次の仕事の途中で初めてその対象に触るエージェントなので、そのまま実行できる形で書く。作って 1 回実行し、意図的に壊した成果物で落ちるのを見るまでは完成ではない（下書き）。

## 1. 利用者でなくリポジトリに聞く

読めば分かることは聞かない。次をリポジトリから答える。

- **成果物と利用者:** 何を作るリポジトリか（コード・文書・スキル・知識・解析。複数なら主なもの 1 つ）。誰が、何を観測して「できた」と判断するか。
- **起動・実行:** その対象の通常の方法（README・package script・Makefile・`pyproject.toml` の scripts・既存の検査・CI があればその定義）。依存の取得も通常の経路で。
- **操作:** 利用者の経路で動かす方法。CLI は実際のコマンド、文書は書かれた手順をそのまま実行、スキルは新しい CLI セッションに依頼を渡す（`delegate`）、解析は入力の版と乱数を固定して再計算。既存の仕組み（テスト・fixture・スクリプト）を先に使う。スキルが対象なら、補助スクリプトの検査だけでは足りない。新しいセッションで、使うべき依頼で使われること、使うべきでない依頼で使われないことを、最初のツール呼び出しで観測する（長く動き続ける操作は `--max-turns` で最初の呼び出しまでに止める）。これが通らないうちは下書き。
- **観測:** 何を証拠にできるか（終了コード、出力、生成ファイル、数値、新しいセッションの成果物）。
- **分離:** 利用者のデータ・設定・常駐を壊さずに動かせるか（一時ディレクトリ、`--data-dir`、worktree）。できなければそう書き、共有の実物を操作しない。

checkout がそのまま動かなければ、先に直すか、正確に報告する。壊れた土台に合わせた手順を書かない。

## 2. スキルを書く

置き場は対象のリポジトリの `.agents/skills/verify-<対象>/`（Codex が読む。`.claude/skills/verify-<対象>` からの相対の symlink で Claude Code にも見せる）。Codex の workspace-write の sandbox は `.agents` を読み取り専用にする（2026-10-17 に実測）。書けなければ正本を `.claude/skills/verify-<対象>/` に置き、`.agents/skills/verify-<対象>` への symlink は、その 1 コマンドだけ sandbox の外での実行を求める。認められなければ、そのコマンドを報告に書く。frontmatter は `name: verify-<対象>` と、対象・成果物・使う場面を書いた `description`。本文の節は次のとおりで、どれも調べた実物に基づく（雛形の文言を残さない）。

- **準備:** 空の状態から使える状態にするコマンドと、使える状態になったと分かる観測。終わったときの片付け。
- **点検:** 「この環境で確かめる価値があるか」を答える読み取り専用の 1 コマンド（版、依存、データの有無、ログイン）。何かおかしいときは最初にこれを実行する。
- **操作:** このリポジトリの実際のコマンド・パス・依頼文。例ではなく実物。
- **証拠:** 何を取り、どこに置くか。利用者の経路を通す（内部の関数やテスト専用の口で済ませない）。操作と結果の状態の両方を取る。副作用（書かれたファイル、変わった数値）も見る。「dry-run」は名前を信じず、実際に何を省くかを観測する。
- **壊して確かめる:** 各検査について、成果物の写しに欠陥を 1 つ入れて落ちることを示す手順（文書なら手順の 1 行を誤りにする、スキルなら使う場面の記述を外す、解析なら入力の 1 行を変える、コードなら判定を 1 か所反転する）。落ちない検査は検査ではない。
- **片付け:** 自分が作ったものだけを消す。名前でプロセスを殺さない。証拠は消さず、残る場所を書く。

補助スクリプトを置くなら実行可能にし、呼び方を本文に書く。

## 3. 機能の一覧を作る

`verify-<対象>/features/README.md` と、利用者から見た機能 1 つにつき 1 ファイル（最初は主なもの 3〜5）。各ファイルの節は `下位の機能`・`利用者の経路`・`動かし方`・`注意`。前提のデータが足りずに確かめられない機能は、失敗として `注意` に理由を書く。通るように手順を弱めない。

## 4. 渡す前に 1 回通す

生成したスキルの手順を、新しい文脈で最初から 1 回実行する: 準備 → 点検 → 機能 1 つの操作 → 証拠 → 壊して確かめる → 片付け。片付けの後に証拠が残っていることを確かめる。落ちた所を直し、失敗した回の後にも片付けを実行する。実行していない手順は下書きとして返し、完成と書かない。代わりの環境で確かめたなら、本物の環境で確かめていない手順を列挙する。

## 5. 届ける

対象のリポジトリの通常の方法で届ける（PR など）。本文に、生成した検証スキルの場所、1 回通したときのコマンドと結果、壊した例とそれが落ちた出力、確かめていない機能を書く。
