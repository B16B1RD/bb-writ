# ドメインを構造で表す

対象のドメインの規則は、散らばった条件分岐でなく、データ構造に入れる。ドメインに合った構造は、ありえない状態を表せなくし、分岐を消す。書くときに選べば安いが、後から取り戻すと作り直しになり、先送りされる。

**なぜ:** 規則が分岐に散ると、新しい場合が来るたびに全部の分岐を探して直す。構造に入れた規則は 1 か所で読めて、破れない。

**適用する場面:**
- 機能を足すと、既存の `if`・`elif` の連鎖が 1 つ伸びるとき。
- 1 つ目の真偽値と常に揃えておく、2 つ目の真偽値を足そうとしたとき。
- モジュールが「読む・検証する・変換する・保存する」の段の名前で分かれ、同じ規則が各段に繰り返されているとき。

**やること:**
- 散らばった真偽値・段階の判定は、状態機械（状態と遷移の表）にする。
- ファイルをまたぐ分岐は、表・登録簿（辞書）・種類を持つ型（Python の `Enum` や `dataclass`、Rust の `enum`）にする。読み方に合わせて、索引・キャッシュ・木などの集まりを選ぶ。
- モジュールは、実行の順番でなく、1 つのドメインの知識（券種の規則、レースの条件）ごとにまとめる。合う構造が無ければ、決して許さない状態と読み方を書き出し、それをちょうど表す構造を探す。

**使わないとき:** いまの形が明快で、局所的で、育つ見込みが無いとき。分岐・重複した規則・ありえない状態を減らさない抽象は、間接の層を足すだけなので作らない。

**確かめる例:** 新しい場合を足す差分が、表や状態の定義への追加で済んでいる。同じ規則を判定する条件式が、複数のファイルに無い。
